# برومت شامل: منظومة المشروع القومي للياقة البدنية بالمعاهد الأزهرية (React)

> **تعليمات للمنفّذ (أداة الإنشاء / المهندس الذكي):** اقرأ هذا الملف بالكامل قبل كتابة أي كود، ثم نفّذ المشروع على مراحل. بعد كل مرحلة لخّص ما تم بإيجاز، وانتظر الموافقة قبل الانتقال للتالية. لا تفترض أي معلومة ناقصة؛ اسأل عنها.

---

## 1) نظرة عامة

أنت مهندس برمجيات أول (Senior Full-Stack Engineer) متخصص في React. المطلوب بناء **منظومة إلكترونية متكاملة** لإدارة ومتابعة **المشروع القومي للياقة البدنية بالمعاهد الأزهرية**، تشمل:

- تسجيل الطلاب وربطهم بالمعهد والفصل والمرحلة.
- إدخال نتائج الاختبارات البدنية للطلاب.
- **تقييم النتائج تلقائيًا** بالاعتماد على ملف المعايير والدرجات المرفق.
- متابعة تقدم الطالب عبر الفصول والأعوام الدراسية.
- لوحات متابعة وتقارير على مستوى الفصل والمعهد والإدارة التعليمية والمنطقة والجمهورية.

## 2) ملفات المدخلات (مرجعية البيانات)

سيتم إرفاق ملفين. **هما المصدر الوحيد للحقيقة (Single Source of Truth)** ويجب ألا تُكتب قيمهما يدويًا داخل الكود.

### الملف الأول: معايير ودرجات الاختبارات البدنية
- يحتوي على الاختبارات البدنية، ومعايير الأداء، والدرجات.
- مقسَّم حسب **المرحلة التعليمية** و**النوع (بنين/بنات)**، وربما حسب العمر أو الصف.
- **المطلوب منك:**
  1. افحص الملف أولًا (الأعمدة، الصيغة، الوحدات، القيم الشاذة) وقدّم **ملخصًا لهيكله** قبل التصميم.
  2. صمّم **سكريبت استيراد (Seed/Import)** يقرأ الملف ويحمّله في قاعدة البيانات.
  3. صمّم نموذج بيانات مرن للمعايير بحيث يمكن تعديلها أو إضافة اختبارات جديدة دون تغيير الكود.
  4. ابنِ **محرّك تقييم (Scoring Engine)** يأخذ: (الاختبار + النتيجة الخام + المرحلة + النوع) ويرجع: (الدرجة + التقدير).
  5. اكتب **اختبارات وحدة** للمحرّك تغطي الحدود (أول/آخر نطاق) والقيم الخارجة عن النطاق.
  6. وضّح كيف تُعامل الاختبارات التي **الأفضل فيها أقل قيمة** (مثل زمن الجري) مقابل التي **الأفضل فيها أعلى قيمة** (مثل عدد التكرارات أو المسافة).

### الملف الثاني: المناطق والإدارات التعليمية
- يحتوي على المناطق الأزهرية والإدارات التعليمية (وربما المعاهد التابعة لها).
- **المطلوب منك:**
  1. افحص الملف وحدّد مستويات الهيكل (محافظة ← منطقة ← إدارة ← معهد) حسب ما هو موجود فعلًا.
  2. استورده في جداول هرمية مرتبطة.
  3. استخدمه في فلاتر التقارير وفي تقييد صلاحيات المستخدمين بنطاقهم الجغرافي/الإداري.
  4. تعامل مع الأخطاء الشائعة: اختلاف كتابة الأسماء، التكرار، الهمزات والتشكيل، الفراغات الزائدة.

> **مهم:** إذا اختلفت بنية الملفين عمّا هو متوقع هنا، **اعرض عليّ الاختلاف أولًا** ثم عدّل التصميم، ولا تخمّن.

## 3) الأدوار والصلاحيات (RBAC)

| الدور | النطاق | الصلاحيات الأساسية |
|---|---|---|
| مدير النظام (مركزي) | الجمهورية | كل شيء، إدارة المعايير والمستخدمين والإعدادات |
| مدير منطقة/إدارة | منطقته/إدارته | عرض وتقارير كل المعاهد التابعة، اعتماد النتائج |
| مدير معهد | معهده | إدارة الطلاب والفصول والمعلمين، عرض التقارير |
| معلم/مدرب لياقة | فصوله | إدخال وتعديل القياسات قبل الاعتماد |
| مشرف/موجّه | نطاق محدد | مراجعة واعتماد النتائج |
| ولي أمر/طالب (اختياري) | نفسه فقط | عرض النتائج فقط |

- كل مستخدم **مقيّد بنطاقه** (لا يرى بيانات خارج معهده/منطقته).
- طبّق الحماية في الواجهة **والخادم معًا**.

## 4) الوحدات الوظيفية

1. **المصادقة وإدارة المستخدمين:** تسجيل دخول، استعادة كلمة المرور، إدارة الأدوار.
2. **الهيكل التنظيمي:** المناطق والإدارات والمعاهد والمراحل والفصول (من الملف الثاني).
3. **ملف الطالب:** الاسم، الرقم القومي/رقم القيد، النوع، تاريخ الميلاد، المعهد، المرحلة، الفصل.
4. **بنك الاختبارات والمعايير:** استيراد وعرض وتعديل (من الملف الأول) مع **سجل إصدارات** للمعايير.
5. **إدخال القياسات:** فردي + جدول إدخال سريع للفصل كاملًا + رفع Excel جماعي مع تقرير أخطاء.
6. **التقييم التلقائي:** الدرجة والتقدير لكل اختبار + الدرجة الكلية ومؤشر كتلة الجسم (BMI) وتصنيفه.
7. **لوحات المتابعة:** مؤشرات رئيسية ورسوم بيانية ومقارنات بين الفصول والمعاهد والفترات.
8. **التقارير والتصدير:** PDF وExcel وطباعة (تقرير طالب، فصل، معهد، إدارة، منطقة).
9. **سجل العمليات (Audit Log):** من عدّل ماذا ومتى.
10. **الإعدادات:** العام الدراسي، الفصل الدراسي، فتح/غلق فترة إدخال النتائج، اعتماد النتائج.

## 5) المتطلبات التقنية

**الواجهة (Frontend)**
- React 18 + TypeScript + Vite
- React Router
- TanStack Query لجلب البيانات، وZustand (أو Redux Toolkit) للحالة العامة
- React Hook Form + Zod للنماذج والتحقق
- Tailwind CSS + shadcn/ui (أو MUI)
- **دعم كامل لـ RTL والعربية** (خط Cairo أو Tajawal)، وإمكانية تغيير اللغة لاحقًا (i18n)
- TanStack Table للجداول (بحث، فرز، ترقيم، تحرير مباشر)
- Recharts للرسوم البيانية
- xlsx لاستيراد/تصدير Excel، وreact-pdf أو jsPDF للـ PDF (مع دعم الخط العربي)

**الخادم (Backend)**
- Node.js + NestJS (أو Express) + TypeScript
- PostgreSQL + Prisma
- JWT + Refresh Tokens
- توثيق الـ API بـ Swagger/OpenAPI

**الجودة والنشر**
- ESLint + Prettier + Husky
- Vitest + React Testing Library + Playwright
- Docker + docker-compose + GitHub Actions

## 6) نموذج البيانات المقترح (يُراجَع بعد فحص الملفين)

- `Region` / `Administration` / `Institute` (هرمي)
- `Stage` / `Grade` / `Classroom`
- `Student` (مرتبط بالمعهد والفصل)
- `AcademicYear` / `Term`
- `FitnessTest` (الاسم، الوحدة، اتجاه التحسّن: أقل أفضل/أعلى أفضل)
- `ScoringStandard` (الاختبار، المرحلة، النوع، نطاق القيم، الدرجة، التقدير، رقم الإصدار)
- `Measurement` (الطالب، الاختبار، القيمة الخام، الفصل الدراسي، المُدخِل، الحالة: مسودة/مُرسَل/معتمد)
- `Result` (الدرجة المحسوبة، التقدير، الإصدار المستخدم من المعايير)
- `User` / `Role` / `UserScope`
- `AuditLog`

اعرض مخطط ERD وشرحًا مختصرًا قبل التنفيذ.

## 7) مراحل التنفيذ

**المرحلة 1: التحليل والتصميم**
- افحص الملفين وقدّم ملخصًا لبنيتهما وأي ملاحظات أو مشكلات في البيانات.
- اقترح ERD وهيكل المجلدات (feature-based) وخريطة الصفحات.
- اقترح نظام تصميم بهوية بصرية مناسبة للأزهر (ألوان هادئة، تباين جيد، خط عربي واضح).
- ✋ **توقف وانتظر الموافقة.**

**المرحلة 2: تهيئة المشروع**
- إنشاء المشروع وضبط الأدوات (ESLint/Prettier/Husky).
- تفعيل RTL والعربية والوضع الفاتح/الداكن.
- طبقة API (Axios + interceptors) وملفات البيئة.

**المرحلة 3: المصادقة والصلاحيات**
- تسجيل الدخول، حماية المسارات، إخفاء العناصر حسب الدور، تقييد النطاق في الخادم.

**المرحلة 4: استيراد البيانات المرجعية**
- سكريبت استيراد الملف الثاني (المناطق والإدارات والمعاهد) مع تقرير نتائج الاستيراد.
- سكريبت استيراد الملف الأول (المعايير والدرجات) مع التحقق من الاتساق (لا فجوات ولا تداخل في النطاقات).
- شاشات عرض وإدارة هذه البيانات.

**المرحلة 5: إدارة الطلاب والفصول**
- CRUD كامل مع بحث وفلاتر.
- استيراد الطلاب من Excel مع تقرير أخطاء قابل للتنزيل.

**المرحلة 6: القياسات والتقييم**
- نماذج الإدخال، التحقق من النطاقات المنطقية (رفض القيم المستحيلة).
- محرّك التقييم مع اختبارات وحدة.
- جدول إدخال سريع للفصل، وحفظ مسودات محليًا لمواجهة ضعف الإنترنت ثم المزامنة.
- دورة الحالة: مسودة ← مُرسَل ← معتمد (مع قفل التعديل بعد الاعتماد).

**المرحلة 7: لوحات المتابعة والتقارير**
- مؤشرات رئيسية: نسب التقدير، متوسط الدرجات، نسبة اكتمال الإدخال، BMI.
- مقارنات بين الفصول والمعاهد والمناطق والفصلين الدراسيين.
- تتبّع تقدم الطالب الفردي.
- التصدير إلى PDF وExcel.

**المرحلة 8: الجودة والأمان**
- اختبارات الوحدة والتكامل وE2E للمسارات الأساسية.
- حماية من XSS/CSRF/SQL Injection، تحديد معدل الطلبات (Rate Limiting)، تشفير كلمات المرور.
- حماية خصوصية بيانات الطلاب (تقليل البيانات المعروضة، تسجيل الاطلاع).
- أداء (Lazy Loading, Pagination) وإمكانية وصول (Accessibility).

**المرحلة 9: النشر والتوثيق**
- Docker وCI/CD وبيئات (تطوير/اختبار/إنتاج) ونسخ احتياطي لقاعدة البيانات.
- README ودليل مستخدم لكل دور ودليل مطوّر.

## 8) متطلبات غير وظيفية

- **متجاوب:** يعمل بكفاءة على الموبايل (المعلمون يدخلون النتائج في الملعب).
- **أداء:** تحمّل عشرات الآلاف من الطلاب وجداول كبيرة دون بطء.
- **توافق:** أحدث إصدارين من Chrome وSafari وEdge وFirefox.
- **تحمّل الأخطاء:** رسائل أخطاء عربية واضحة، وعدم فقد البيانات عند انقطاع الاتصال.
- **قابلية التوسّع:** إضافة اختبار أو مرحلة أو معيار جديد دون تعديل الكود.

---

## 9) قواعد العمل

1. كود نظيف مقسّم لمكوّنات صغيرة قابلة لإعادة الاستخدام، مع TypeScript صارم.
2. لا تكتب أي معايير أو درجات أو أسماء مناطق ثابتة داخل الكود؛ كلها من قاعدة البيانات المستوردة.
3. أي قيمة ناقصة أو غامضة في الملفين: **اسأل ولا تخمّن**.
4. اشرح كل قرار تصميم مهم في سطرين.
5. بعد كل مرحلة: ملخص قصير + كيفية تشغيل/اختبار ما تم + ما سيُنفَّذ بعدها.
